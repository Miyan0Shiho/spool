## 0. GPT-6 输入摘要（v1.3 更新）

> 如果你（GPT-6）只读这一节，应该能立即理解产品的全貌。

### 一句话定位

**一个开源桌面 Agent 软件——用户只说需求，系统主动感知 + 调度流程 + 持续跟进，产出最新的专业内容；用户也能让 AI 帮自己创建专属流程。**

### 核心机制

**双层飞轮 + 主动感知任务**：
- **团队层**：推送高质量公共流程模板给所有用户（持续改进）
- **用户层**：用户通过 Agent 对话自助创建 / 修改私有流程（零门槛）
- **主动感知**：模型持续感知目标 / 上下文 / 证据 / 行为 / 环境，发现"值得推进的工作"时主动建议

### 关键约束

- **用户不感知差异化**——产品差异化隐藏在行为中，不在 UI 中
- **用户不感知"流程"概念**——只感知"输入需求 → 得到结果"
- **模型是基础设施**——可接入任意模型，不是差异化点
- **不做平台 / 流程市场 / 社区贡献**——做产品，不做平台
- **不开源贡献**——开源代码可读可学习，但不开放外部贡献流程模板

### 参考样板

## 7. 核心命题（N1–N5，v1.3 修订）

- **N1 流程作为一等公民**：可定义、可执行、可观察、可回放、可版本化、可对比、可改进——**对用户隐藏，对产品内部核心**
- **N2 流程层次**：
  - **L1** 单步工具调用（模型决定调用什么工具）
  - **L2** 多步有序流程（结构化的步骤序列 + 转换条件）
  - **L3** 迭代 / 自适应流程（流程可重入、自适应反馈）
  - **L4** 多 Agent 协作流程（多角色分工、协同）
- **N3 借鉴 / 自研分层**：借鉴 L1 工具调用层 + 部分 L2 流程 + Agent 执行引擎；自研 L2 完整 + L3 + L4 + 流程引擎架构 + **双层飞轮机制 + 主动感知能力**
- **N4 流程模板 = 双层资产（v1.3 GPT-6 具体化）**：
  - **公共流程模板**：定义**质量底线**（完成条件、证据类型、冲突检查、判断点），团队维护
  - **私有流程模板**：用户**反复表达的偏好**（不是用户编排的复杂 workflow），用户维护
  - **关键洞察**：公共 = 必须满足的；私有 = 倾向应用的；Agent 根据任务临时生成执行路径
- **N5 技术护城河 = 三层持续运转能力（v1.3 GPT-6 修订）**：

  - **系统层**：逐渐理解某个用户的研究偏好、适用范围、主动性边界

## 8. 核心机制：双层飞轮 + 主动感知任务（v1.3 重定）

### 8.1 双层飞轮

```
┌────────────────────────────────────────────┐
│  团队层（Public Pipeline）                 │
│  • 推送新公共流程模板给所有用户            │
│  • 推送公共流程模板更新                    │
│  • 接收用户使用反馈 → 持续优化             │
│  • 用户使用元数据（脱敏）作为改进信号      │
└──────────────┬─────────────────────────────┘
               │ 推送 / 反馈
               ↓
┌────────────────────────────────────────────┐
│  用户层（Private Pipeline）                │
│  • 用户通过 Agent 对话创建私有流程         │
│  • 用户通过 Agent 对话修改私有流程         │
│  • 用户调用自己的私有流程                  │
│  • 私有流程对其他用户不可见                │
│  • 私有流程不分享                          │
└────────────────────────────────────────────┘
```

### 8.2 双层的精确定义（v1.3 GPT-6 具体化）

| 层 | 职责 | 不是 |
|---|---|---|
| **公共流程** | 定义质量底线（完成条件、证据类型、冲突检查、判断点） | 不是固定动作清单、不是 Agent 角色链 |
| **私有流程** | 用户反复表达的偏好（什么时候被提醒 / 接受什么主动性 / 偏好哪些来源） | 不是用户编排的复杂 workflow |
| **Agent** | 根据任务临时生成执行路径——可改变路径，但不能无理由丢失关键证据 / 质量判断 / 用户约束 | 不是流程的机械执行者 |

**判断规则（v1.3 GPT-6）**：

> 去掉某个元素会让结果**无法验证 / 容易误导 / 违反用户边界**，它就应成为质量要求（结构化）；否则它更可能只是**可替换的执行策略**（灵活）。

### 8.3 必须结构化的（不可灵活）

- 目标是否被正确解释
- 关键结论是否有证据
- 证据与结论是否明显矛盾
- 是否区分事实、推断、建议
- 是否检查反例或反方证据
- 是否暴露重要不确定性
- 是否满足用户明确约束
- 是否触发安全 / 权限 / 数据边界

### 8.4 可以灵活的（不可结构化）

- 搜索顺序和来源数量
- 是否并行搜索
- 是否先推理后查证
- 是否拆分或合并子问题
- 是否重复某一步
- 是否使用一个或多个 Agent
- 工具选择、停止时机、表达详细程度

### 8.5 主动感知任务（v1.3 新增）

模型不应凭空主动产生任务，而应**持续感知目标 / 上下文 / 证据 / 行为 / 环境**，在发现"值得推进的工作"时提出行动候选。

```
持续感知
→ 发现变化或缺口
→ 判断价值
→ 形成行动候选
→ 选择介入方式
→ 请求确认或执行
```

#### 五类感知信号

1. **目标信号**——长期目标 vs 单次任务
2. **未完成信号**——暂时停止但未真正完成的工作
3. **证据信号**——证据状态变化（冲突、单一来源、缺少反方）
4. **行为信号**——重复行为可能说明未明确表达的需求
5. **环境信号**——工作区新增文件 / 项目状态变化（用户授权范围内）

#### 四级介入

| 等级 | 形式 | 第一版建议 |
|---|---|---|
| **A. 静默记录** | 不打扰用户 | ✅ 启用 |
| **B. 顺带提示** | 在当前结果中自然提及 | ✅ 启用 |
| **C. 主动建议** | 用户决定是否执行 | ✅ 启用（最重要的形式） |
| **D. 受授权自动执行** | 低风险、边界清晰、用户授权 | ⏳ 后续版本 |

#### 第一版主动性边界（v1.3 GPT-6 建议）

**最小闭环**：

```
用户完成研究
→ 系统识别未完成问题或证据缺口
→ 系统给出主动建议
→ 用户确认
→ Agent 执行后续研究
→ 结果回写到原研究上下文
```

**第一版验证三类主动建议**：
1. **证据复核**——发现关键结论证据不足 / 冲突 / 缺少反方观点
2. **研究推进**——发现当前材料已经足够进入下一阶段
3. **工作方式沉淀**——发现用户反复做同类修改，建议形成个人工作偏好

**第一版暂不做**：
- 无授权后台长时间运行
- 自动操作外部系统
- 自动修改用户重要文件
- 全天候监听所有本地内容
- 自动推断用户人生或职业目标
- 自动创建大量定时任务
- 多 Agent 常驻协作
- 为了显得主动而频繁通知用户

### 8.6 与双层飞轮的关系（v1.3 GPT-6）

| 层 | 在主动性上的职责 |
|---|---|
| **公共层** | 什么值得做、什么质量缺口重要 |
| **私有层** | 对这个用户来说，什么时候值得做、以什么方式提醒 |

这可能形成一种重要的长期资产：

> **用户如何决定下一项工作**——这本身就是核心护城河的一部分。

### 8.7 与多 Agent 的关系（v1.3 GPT-6）

多 Agent 不应被动地由每个新任务自动生成：

```
发现��务
→ 判断是否需要独立视角
→ 判断是否需要并行证据
→ 判断额外成本是否值得
→ 必要时临时形成协作
→ 汇聚成面向用户的结果
```

只有在以下条件才值得使用多 Agent：
- 子问题相互独立
- 需要真正不同的判断视角
- 存在证据冲突或方案竞争
- 并行执行能明显降低时间
- 有明确的汇聚和裁决方式

否则，一个 Agent 完成任务更好。

**v1.3**：**双层飞轮 = 护城河假设**——需通过质量提升 / 返工减少 / 个性化沉淀 / 用户控制感的综合验证

### 19.10 v1.2 → v1.3：用户画像的决策（不收窄）

**v1.2**：用户 = 不需要懂技术的任何人
