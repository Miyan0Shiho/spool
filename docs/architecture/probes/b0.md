# B0 基础验证报告

> 状态：有界探针已在 Node `24.21.0` 上复跑通过；技术栈、依赖和实现布局已选定。
> B1-B5 后续核心验收已完成；硬件断电实验按 DEC-044 豁免且不承诺，真实 provider
> 已由 DeepSeek 验证。
>
> 日期：2026-09-19
>
> 上位文档：[P0 实现计划](../p0-plan.md)、[执行契约](../execution-contracts.md)。

## 1. 结论

B0 证明当前机器可以在 macOS 上完成 SQLite 事务存储、进程组取消、Seatbelt 有界
执行、SSE provider 协议处理和 tarball 安装实验。但它同时发现三个不能忽略的限制：

1. 当前 Node `23.11.0` 已 EOL，其内置 SQLite `3.49.1` 落在官方 WAL-reset 缺陷
   影响范围内，不能作为采用 WAL 的发布基线。
2. macOS `sandbox-exec` 可以限制普通路径写入、symlink 穿越、网络和 fork，但允许
   目录中的预建 hard link 仍可修改目录外同 inode 文件，因此只能报告
   `partial` enforcement，不能声明完整文件系统隔离。
3. 本地 mock 证明客户端 SSE 状态机和 opaque artifact 可无损处理，但还没有真实
   provider 凭据、TLS、代理和真实 reasoning/signature 验证。

锁定 Node `24.21.0` LTS，实测 SQLite 为 `3.53.4`，满足 `>= 3.51.3` 要求并已在
该 runtime 上复跑全部五组探针。TypeScript 仅作为开发/构建依赖，生产 runtime 不
新增 npm 依赖。若升级 Node，必须重新执行同一矩阵后才能更新锁定版本。

## 3. 存储探针

### 3.1 通过项

| 检查 | 结果 |
|---|---|
| `node:sqlite` 加载 | 默认可用，无 experimental flag；会输出 ExperimentalWarning |
| 事务提交/回滚 | 提交记录保留，回滚记录不可见 |
| WAL 与同步配置 | `journal_mode=wal`、`synchronous=2`（FULL）可设置 |
| 外键 | `PRAGMA foreign_keys = 1` 在当前连接启用 |
| 单写者冲突 | 零等待的第二写者得到 `database is locked` |
| 有界等待 | `busy_timeout=3000` 时，等待写者在对方提交后成功 |
| WAL 并发读者 | 未提交写事务存在时，独立读连接仍可读 |
| 独立进程重启 | 新进程读取到已提交数据，`integrity_check=ok` |
| 进程崩溃前缀 | `SIGKILL` 后恢复 30 条连续提交，无编号缺口，未提交事务不可见 |
| schema 升级 | `user_version: 1 -> 2`；失败迁移回滚后 schema 与版本保持原状 |
| 在线备份 | Node 原生 `backup()` 成功，备份库行数和完整性检查通过 |

关键输出：

```text
immediate writer:
code=ERR_SQLITE_ERROR, errcode=5, errstr=database is locked

waiting writer:
ok=true, busyTimeoutMs=3000

crash reopen:
count=30, minSeq=1, maxSeq=30, distinctCount=30, gaps=0
integrity=ok
hasUncommitted=0

backup:
sourceCount=10
backupCount=10
backupIntegrity=ok
```

### 3.2 失败与未验证

- Node 23 已于 2025-06-01 EOL，不能作为新产品的长期 runtime。
- 当前 SQLite `3.49.1` 低于 WAL-reset 缺陷的修复版本 `3.51.3`，不能把当前
  Node 组合作为采用 WAL 的发布基线。
- `SIGKILL` 后的前缀恢复不等于断电 durability；本轮没有操作系统崩溃、磁盘缓存
  丢失或硬件断电实验，K01 的对应部分仍未验证。后续用户已按 DEC-044 明确豁免
  该硬件实验，但从证据层面仍不能宣称断电 durability 已通过。
- `node:sqlite` 在当前版本仍是实验 API；目标 Node 24 也只是 release candidate
  等级。存储层必须保持窄接口，并允许升级 runtime 后重跑同一探针。
- 本轮没有证明多进程长期同时写入的产品语义。P0 仍采用单一 storage owner，
  SQLite busy error 只作为防御。

Node `24.21.0` 复测没有复现 Node 23 的存储禁用条件：SQLite `3.53.4` 已高于
WAL-reset 修复下限，事务、WAL、锁等待、并发读、崩溃前缀、迁移和 backup 探针均
通过。`node:sqlite` API 稳定性风险仍需通过窄接口隔离。

### 3.3 路线选择

Homebrew Python 3.11 使用 SQLite `3.53.4`，功能测试通过，但默认 PATH 中的
`python3` 实际可能是另一版本和更旧 SQLite。Python 路线会引入解释器固定和独立
分发问题，不能因为当前探针成功就忽略安装路径风险。

推荐 Node 24 LTS 路线，原因是对 CLI/子进程/标准库测试和 JSON 协议处理更直接，
且可以保持零 runtime npm 依赖。Node 24.21.0 的 Homebrew formula 依赖 SQLite
3.53.4，但 Node 内嵌版本不能仅凭公式推断。该推荐不是 Node 24 的实测结论；批准
安装后必须先记录实际 `process.versions.sqlite` 并重跑本报告第 3 节。

## 4. 进程与执行安全探针

### 4.1 进程取消

| 检查 | 结果 |
|---|---|
| `detached` 新进程组 | 通过，`pgid == pid` |
| 对负 PGID 发 `SIGTERM` | 通过，Shell 和孙进程均消失 |
| 仅对父 PID 发信号 | 失败，Shell 退出但孙进程被 `ppid=1` 收养并继续运行 |
| 父进程正常退出 | 子进程可成为孤儿 |
| 父进程 `SIGKILL` | 子进程可成为孤儿 |
| stdout/stderr/退出码 | 可分别读取，退出码 `7` 正确 |
| PID 复用防护 | 通过，PID + 微秒级启动时间可拒绝 stale identity |
| Seatbelt 下取消 | 通过，PGID 取消后测试进程组为空 |

关键输出：

```text
group cancel after:
{"code":143,"signal":null}
groupRows: []

pid-only cancel after:
exit: {"code":null,"signal":"SIGTERM"}
close: timeout
grandchild: ppid=1, pgid=<test pgid>, still alive
```

`exit`、`close`、进程组静默和残留进程不是同一个事实。输出 pipe 可能被已孤立的
孙进程持有，因此 `close` 超时不能单独证明命令仍存活；恢复时 PID、PGID 或启动
时间任一不匹配就禁止发信号并记录 `outcome-unknown`。

### 4.2 macOS Seatbelt

| 维度 | 结果 | 边界 |
|---|---|---|
| 指定目录内写入 | 允许 | 对照通过 |
| 目录外普通写入 | 拒绝 | `Operation not permitted` |
| symlink 穿越 | 拒绝 | 对照 sentinel 未变化 |
| 预建 hard link 写入 | 逃逸 | 目录外同 inode 文件被修改 |
| 沙箱内新建 hard link | 被阻止 | 目录外 sentinel 未变化 |
| TCP/UDP 网络拒绝 | 通过 | 代表性 loopback 测试返回 `EPERM` |
| `process-fork` 拒绝 | 通过 | 子进程创建返回 `EPERM` |
| profile 缺失或畸形 | fail closed | `sandbox-exec` 返回非零，sentinel 未创建 |

因此 Seatbelt 可以作为首个受控执行后端，但只能报告 `partial`。若某项策略要求
“任意代码不能修改 workspace 外文件”，当前后端不能兑现，必须 fail closed，
不能静默使用 partial 或 unsandboxed 模式。

未验证 IPv6、AF_UNIX、代理隧道、其他 macOS 版本、Intel Mac、`sandbox-exec`
未来移除以及扫描与执行之间的 hard-link TOCTOU。

## 5. Provider 协议探针

本地 HTTP/SSE mock 共执行 12 项检查，全部通过：

```text
PASS text_delta_and_usage
PASS usage_missing_is_unknown
PASS multibyte_utf8_split
PASS tool_call_arguments_reassembled
PASS tool_result_second_turn
PASS interrupted_stream_preserves_partial
PASS abort_signal_cancels_stream
PASS structured_http_error
PASS structured_sse_error
PASS malformed_json_is_structured
PASS truncated_sse_is_structured
PASS opaque_artifact_exact_round_trip
SUMMARY {"pass":12,"fail":0,"total":12,"observedRequests":15}
```

推荐的状态机为：

```text
request-open
  -> message-start
  -> content-block-start(index)
  -> content-block-delta*
  -> content-block-stop(index)
  -> ...
  -> message-delta(stop_reason/usage)
  -> message-stop
  -> committed
```

任意阶段可进入 `http-error`、`sse-error`、`parse-error`、`stream-interrupted`、
`aborted` 或 `stream-incomplete`。失败后该 attempt 必须成为终态，不能继续派发
该 attempt 的工具。`usage` 缺失必须记为 `unknown`，不能写成零。

工具调用参数只能在完整 block 结束并成功解析 JSON 后形成候选调用；权限检查和
完整响应结算完成后才允许派发。opaque artifact 必须保留 block 类型、原始 start
对象、有序 delta、签名字段和未知字段，不能只保存合并后的 thinking 文本。

本地 mock 不证明真实 provider 接受相同字段。TLS、代理、压缩、真实断流、429/5xx、
request ID、Anthropic thinking/signature 和 OpenAI-compatible 差异仍需真实凭据
与外部网络验证。

首选发布路线是编译后的 npm 包和本地 tarball 安装：

- `npm pack` 生成最小、确定性的发布包。
- 干净目录安装验证 `files`、`bin`、package integrity 和首次启动。
- 不依赖仓库源码树、全局模块、`.references` 或在线 registry。
- 源码直接启动只作为开发模式。
- SEA 单文件发布需要额外注入、签名、公证、升级和 native asset 验证，暂不采用。

这些命令已在 Node `24.21.0` 上复跑通过。B0 结论只适用于报告记录的版本和环境。

存储、进程和 Seatbelt 探针会生成数据库、raw NDJSON 和临时进程记录，这些仓库内
路径已由 `.gitignore` 排除；安装探针改为在系统 `TMPDIR` 下创建唯一工作目录并
打印路径，不向仓库写入打包产物。断电 durability 不在该套件中，不能用 `SIGKILL`
结果代替。
