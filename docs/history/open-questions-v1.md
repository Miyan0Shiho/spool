## Q1：流程灵活性 vs 结构性

**发现日期**：2026-09-15
**状态**：✅ 已解决（v1.3 集成 GPT-6 第一批回答）

### 一句话陈述

> **在不约束用户的前提下，如何让流程既适配多样性需求（用户每次需求不同），又保证专业质量（每次结果都专业）？**

### v1.3 已沉淀的答案（GPT-6 具体化）

#### 三层定义

| 层 | 职责 | 不是 |
|---|---|---|
| **公共流程** | 定义质量底线（完成条件、证据类型、冲突检查、判断点） | 不是固定动作清单、不是 Agent 角色链 |
| **私有流程** | 用户反复表达的偏好（什么时候被提醒 / 接受什么主动性 / 偏好哪些来源） | 不是用户编排的复杂 workflow |
| **Agent** | 根据任务临时生成执行路径——可改变路径，但不能无理由丢失关键证据 / 质量判断 / 用户约束 | 不是流程的机械执行者 |

#### 必须结构化的（不可灵活）

- 目标是否被正确解释
- 关键结论是否有证据
- 证据与结论是否明显矛盾
- 是否区分事实、推断、建议
- 是否检查反例或反方证据
- 是否暴露重要不确定性
- 是否满足用户明确约束
- 是否触发安全 / 权限 / 数据边界

#### 可以灵活的（不可结构化）

- 搜索顺序和来源数量
- 是否并行搜索
- 是否先推理后查证
- 是否拆分或合并子问题
- 是否重复某一步
- 是否使用一个或多个 Agent
- 工具选择、停止时机、表达详细程度

#### 判断规则（v1.3 GPT-6）

> 去掉某个元素会让结果**无法验证 / 容易误导 / 违反用户边界**，它就应成为质量要求（结构化）；否则它更可能只是**可替换的执行策略**（灵活）。

#### 验证方式（不测试步骤执行率）

- 不同研究任务是否都能形成合理问题边界
- Agent 是否能跳过无关步骤、重做失败部分、改变搜索策略
- 关键结论是否稳定保留支持证据、反方证据、不确定性
- 用户偏好是否被应用到适用任务，没有污染其他任务
- 相似任务的质量下限是否稳定，不依赖固定工具顺序

### 仍待 GPT-6 设计的具体细节

1. 公共流程模板的"结构化程度"应该多大——是工具调用清单、阶段定义、还是更高层抽象？
2. 私有流程如何"派生"自公共流程——基于公共流程复制修改，还是完全独立创建？
3. 当用户通过对话自助创建流程时，Agent 扮演什么角色——引导者、设计者、还是执行者？
4. 流程的"灵活性边界"是什么——是不是有些流程必须严格遵守（如数据安全）？
5. 如何让用户**事后**理解"流程做了什么"——可观察性 vs 透明度的关系？

## Q3：与现有 AGI 范式的差异化

**发现日期**：v1 文档确认
**状态**：✅ 已解决（v1.3 集成 GPT-6 第一批回答）

### 一句话陈述

> **我们的护城河（双层飞轮 + 主动感知）在现有 AGI 范式中是否已有对应物？我们的差异化是真差异化还是伪差异化？**

### v1.3 已沉淀的答案

#### 核心结论

1. "有流程""有多 Agent""能自然语言创建工作流"都不能单独构成差异化
2. spool 的差异化应是：用户不需要设计流程，Agent 也不只是完成一次性任务，而是持续结合公共专业方法和用户个人工作方式
3. **双层飞轮目前是护城河假设，不是已经成立的护城河**
4. 流程格式、角色设计和界面容易被复制；长期积累的质量评估、任务适配和用户偏好沉淀更难复制
5. spool 的竞争单位不是"更强的单个 Agent"，而是"会逐渐适配用户、同时保留专业质量底线的研究工作系统"

#### 与 Agent 开发框架（LangChain / LangGraph / AutoGen / CrewAI / Swarm）

> 框架解决开发者如何构造 Agent；spool 解决普通用户如何获得一套逐渐适合自己的专业工作方式。

spool 不与它们竞争编排能力，而位于终端用户体验的更上层。

#### 与工作流引擎（Temporal / Prefect）

> 工作流引擎关注流程是否可靠地执行；spool 还必须判断下一步是否值得做，以及结论是否足够可信。

可借鉴可靠执行和回放，但不能把研究过程降格为固定业务流程。

#### 与专家流程 / 多 Agent 产品（MetaGPT 等）

研究任务中更重要的是：
- 是否找到相反证据
- 是否存在竞争性解释
- 是否识别结论的脆弱点
- 是否知道何时停止扩展任务

多 Agent 应围绕证据冲突和判断差异**按需形成**，而不是预先固定一组虚拟岗位。

#### 与 n8n / Dify / Coze

- 其他产品让用户搭建和管理**显式工作流**
- spool 让用户表达**目标**，Agent 在后台形成和调整工作方式
- 其他产品的核心资产是节点、连接器、应用配置
- spool 第一版的核心资产是**研究判断、证据质量和用户长期偏好**

#### 与完整 Agent 产品（Codex / ChatGPT / Devin / Manus / TRAE）

spool 不能仅以"也能调用工具""也能长任务""也能多 Agent"作为差异化。

spool 应逐渐掌握：
- 用户反复关注的问题
- 用户认可或拒绝的证据类型
- 用户常用的判断标准
- ��些未完成事项值得继续
- 哪些结论需要复核
- 用户最近的研究目标和上下文

但主动性应优先表现为**发现和建议**，而不是无授权的持续后台行动。

#### 双层飞轮的护城河判断

**潜在护城河来自三种复合积累**：

1. **团队**：知道哪些研究输出容易出错、哪些反驳有效、哪些质量门值得保留
2. **系统**：逐渐理解某个用户的研究偏好、适用范围、主动性边界
3. **用户**：接受 / 修改 / 否定 / 重做结果形成反馈，反向改善公共质量基线

**双层飞轮只有在质量提升、返工减少、个性化沉淀和用户控制感都被真实验证后，才可能成为可持续护城河。**

### 仍待 GPT-6 / 后续讨论

- 三种复合积累如何度量
- 如何判断护城河假设已被验证
- 主动感知 + 双层飞轮的护城河复合效应

## Q4：目标用户画像

**发现日期**：v1 文档确认
**状态**：✅ 已解决（v1.3 决策：**不收窄**）

### 一句话陈述

> **用户 = 不需要懂技术的任何人**

### v1.3 决策

**保持 v1.2 的判断**——用户画像**不收窄**。

GPT-6 建议优先服务"研究型知识工作者"（研究生 / 独立研究者 / 技术型职场研究员），但**v1.3 决策不采纳**。

**理由**（隐含）：
- 产品定位 = 能力平权
- 收窄用户画像违背产品定位
- 第一版可以从小范围验证，但**目标用户仍是任何人**

### GPT-6 建议（作为后续讨论参考，不强制）

#### 推荐用户画像

核心用户是"独立研究型知识工作者"：
- 硕士生、博士生
- 需要持续查资料和写分析报告的研究人员
- 技术型职场人士
- 独立开发者或研究型创作者
- 需要独立完成行业 / 技术 / 产品调研的人

#### 候选群体比较

| 用户群体 | 价值感知 | 使用频率 | 反馈质量 | 双层飞轮验证 |
|---|---:|---:|---:|---:|
| 学术研究者 | 高 | 中高 | 很高 | 很高 |
| 职场研究员 | 高 | 高 | 中高 | 高 |
| 独立创作者 | 中高 | 高 | 中 | 中 |
| 决策支持用户 | 很高 | 中 | 高 | 中高 |
| 日常用户 | 低到中 | 不稳定 | 低 | 低 |

### 仍待 GPT-6 完成的（Q4 的具体子问题）

- 哪个用户群体最能体现"双层飞轮 + 主动感知"的价值
- 哪个用户群体最容易获得早期采用者
- 哪个用户群体能形成可持续反馈
- 第一版应服务"最广用户"还是"最深需求"
