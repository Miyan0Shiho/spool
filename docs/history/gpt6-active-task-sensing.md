## 1. 核心定义

模型不应该凭空主动产生任务，而应该持续感知目标、上下文、证据和用户行为，在发现存在“值得推进的工作”时提出行动候选。

主动性不是简单的后台运行，也不是传统定时任务的升级版。它更接近一个任务发现系统：

```text
持续感知
→ 发现变化或缺口
→ 判断价值
→ 形成行动候选
→ 选择介入方式
→ 请求确认或执行
```

核心问题不是“如何让模型主动”，而是：

> 系统如何发现值得推进的工作，并在合适时机以合适强度介入。

## 2. 模型需要感知的信号

### 2.1 目标信号

识别用户的长期目标，而不只记录单次任务。

示例：

- 正在完成一篇论文。
- 正在研究一个技术方向。
- 正在准备一份行业报告。
- 正在持续跟踪一个开放问题。
- 正在建立某个知识领域。

一次对话可以产生短期任务，也可能暴露一个需要用户确认的长期目标假设。

### 2.2 未完成信号

识别暂时停止但尚未真正完成的工作：

- 问题没有回答完。
- 结论只是暂时判断。
- 已找到资料但没有比较。
- 分支被用户中途打断。
- 开放问题反复出现。
- 材料已经足够进入下一阶段。

历史记录回答“过去发生了什么”，未完成信号回答“现在还有什么值得继续做”。

### 2.3 证据信号

研究场景中，主动任务可以由证据状态变化触发：

- 新资料与已有结论冲突。
- 关键结论只有单一来源支持。
- 结论缺少反方证据。
- 关键来源失效或不可访问。
- 多个来源使用不同定义。
- 新输入改变了原问题边界。

主动性不只是“定期搜索”，也可以是“当结论可靠性发生变化时提醒复核”。

### 2.4 行为信号

用户的重复行为可能说明存在尚未明确表达的需求：

- 连续多次做类似调研。
- 反复要求补充反驳。
- 经常手动修正同一种错误。
- 经常要求相同的交付格式。
- 反复表达“以后都这样处理”。
- 频繁打开某个主题但没有形成阶段性总结。

行为信号可以触发：

1. 是否把重复行为沉淀为私有工作方式。
2. 是否存在一个更高层、尚未明确提出的研究目标。

### 2.5 环境信号

在用户明确授权的范围内，系统可以感知：

- 工作区新增文件。
- 项目状态变化。
- 研究目录出现新资料。
- 外部数据或订阅内容更新。
- 长期任务的输入条件发生变化。

第一版应限制在用户主动授权的工作区和资料范围内，避免过度监控与权限边界不清。

## 3. 主动任务发现链路

### 3.1 感知

收集可能改变用户工作状态的信号：

- 新对话。
- 新文件。
- 用户修改。
- 未完成任务。
- 研究目标变化。
- 证据变化。
- 用户重复行为。

### 3.2 识别

把信号转换为可能的工作机会：

- 补充证据。
- 复核结论。
- 合并资料。
- 推进长期目标。
- 沉淀用户偏好。
- 清理重复工作。
- 拆分过大的问题。

### 3.3 评估

不是所有发现都值得变成任务。至少需要评估：

- 与用户目标的相关性。
- 潜在收益。
- 紧迫性。
- 识别置信度。
- 执行成本。
- 打扰成本。
- 是否需要用户决策。
- 是否涉及外部副作用。
- 如果现在不做，是否会让后续工作更困难。

### 3.4 形成任务候选

系统不应直接把内部判断变成执行动作，而应先形成可理解的行动候选：

```text
发现：
已有结论的关键证据只有一个来源。

建议：
补充独立来源，并检查是否存在反方证据。

价值：
如果该结论将用于最终报告，补充证据可以降低误判风险。

成本：
预计一次短研究任务。

状态：
等待用户确认。
```

用户需要理解的是“为什么值得做”，而不是被迫管理内部流程。

## 4. 主动介入的四个等级

### A. 静默记录

适用于低价值、低紧迫性或低置信度的发现。

示例：

- 记录用户反复使用的表达。
- 记录可能的长期主题。
- 标记未来可合并的资料。

不打扰用户。

### B. 在当前结果中顺带提示

适用于与当前任务自然相关的发现。

示例：

> 这项研究与你之前的两个问题有关，我已将它们归并为一个待继续方向。

不额外制造明显的任务管理负担。

### C. 主动建议

适用于有明确价值、但需要用户决定的工作。

示例：

> 你当前的研究���论有一处证据冲突。要不要我专门做一次反驳和来源复核？

这是第一版最重要的主动形式。

### D. 受授权自动执行

适用于低风险、边界清晰且用户已经授权的任务：

- 整理用户指定目录中的新论文。
- 检查已有报告中的来源是否失效。
- 归并重复资料。
- 对明确指定主题执行增量摘要。

不适用于：

- 对外发送内容。
- 修改重要文件。
- 代表用户做决策。
- 大范围高成本运行。
- 依赖重大推断的自动行动。

## 5. 与定时任务的关系

定时任务是主动性的一个触发器，不是主动性的核心定义：

```text
主动性 =
时间触发
+ 事件触发
+ 目标触发
+ 证据触发
+ 行为模式触发
```

### 定时任务适合

- 定期检查指定研究主题是否出现新资料。
- 定期复核长期报告。
- 在截止日期前准备阶段性材料。
- 整理用户授权的资料目录。
- 到指定时间提醒用户重新评估结论。

### 定时任务不适合

- 每天无条件生成摘要。
- 仅因时间到达就启动完整研究流程。
- 没有新信号却持续运行多 Agent。
- 把“定时”误认为“有价值”。
- 让用户维护大量自动化规则。

更合理的方向是：用户表达长期目标和关注方向，系统判断哪些时间点值得检查；定时只是系统可选择的一种底层触发方式。

## 6. 如何判断用户真正需要什么

不能把模型猜测直接当成用户真实需求。需要区分：

| 状态 | 含义 | 产品行为 |
|---|---|---|
| 明确需求 | 用户直接表达 | 可以执行 |
| 高置信隐含需求 | 多次稳定行为指向同一目标 | 可以建议，不应直接执行 |
| 弱信号猜测 | 单次行为或模糊上下文 | 静默记录或忽略 |

示例：

用户连续三次研究“Agent memory”，系统可以判断：

> 你可能正在形成一个长期研究主题。

但不能直接判断用户要发表论文。正确行为是：

> 我发现你最近多次研究 Agent memory。它可能已经成为一个持续主题。要不要把后续资料、开放问题和结论集中起来？

原则：

> 模型可以提出目标假设，但只有用户确认后，才能把它升级为长期目标。

## 7. 与双层飞轮的关系

### 团队层

公共流程可以定义：

- 哪些未完成状态值得提醒。
- 哪些证据缺口需要复核。
- 哪些研究结论通常需要反驳。
- 哪些阶段性成果值得推进。
- 哪些任务可以低风险自动执行。

### 用户层

私有流程可以沉淀：

- 用户喜欢什么时候被提醒。
- 用户接受什么程度的主动性。
- 用户长期关注哪些主题。
- 用户希望先做什么、后做什么。
- 哪些建议容易被接受。
- 哪些任务虽然有价值，但用户不希望系统主动触发。

双层飞轮在主动性上的关系是：

```text
公共层：
什么值得做、什么质量缺口重要

私有层：
对这个用户来说，什么时候值得做、以什么方式提醒
```

这可能形成一种重要的长期资产：

> 用户如何决定下一项工作。

## 8. 与多 Agent 的关系

多 Agent 不应被动地由每个新任务自动生成：

```text
发现任务
→ 自动拆分
→ 自动生成多个 Agent
→ 产生大量中间结果
→ 用户重新管理复杂度
```

更合理的路径是：

```text
发现任务
→ 判断是否需要独立视角
→ 判断是否需要并行证据
→ 判断额外成本是否值得
→ 必要时临时形成协作
→ 汇聚成面向用户的结果
```

只有在以下条件下才值得使用多 Agent：

- 子问题相互独立。
- 需要真正不同的判断视角。
- 存在证据冲突或方案竞争。
- 并行执行能明显降低时间。
- 有明确的汇聚和裁决方式。

否则，一个 Agent 完成任务更好。

## 9. 第一版主动性的建议边界

第一版不追求 Agent 自己持续工作，而验证一个最小闭环：

```text
用户完成一次研究任务
→ 系统识别一个未完成问题或证据缺口
→ 系统给出一条主动建议
→ 用户确认
→ Agent 执行后续研究
→ 结果回写到原研究上下文
```

第一版优先验证三类主动建议：

1. 证据复核：发现关键结论证据不足、冲突或缺少反方观点。
2. 研究推进：发现当前材料已经足够进入下一阶段。
3. 工作方式沉淀：发现用户反复做同类修改，建议形成个人工作偏好。

第一版暂不做：

- 无授权后台长时间运行。
- 自动操作外部系统。
- 自动修改用户重要文件。
- 全天候监听所有本地内容。
- 自动推断用户人生或职业目标。
- 自动创建大量定时任务。
- 多 Agent 常驻协作。
- 为了显得主动而频繁通知用户。

## 10. 核心开放问题

1. 什么信号足以让 Agent 提出主动建议？
2. 什么情况下建议可以自动执行？
3. 如何控制主动建议的频率和打扰成本？
4. 如何让用户知道建议的依据，但不被迫查看复杂流程？
5. 如何区分“用户暂时没做”和“用户明确不想做”？
6. 如何处理多个长期目标之间的竞争？
7. 用户确认过的主动性授权如何撤销或缩小范围？
8. 如何评估主动建议是否真正推进了用户目标，而不是制造了更多任务？
